подписываешь комментарии на доске (например при закрытии задач).

Правила оркестрирования в этом репозитории:

- Это **форк** апстрима BEDOLAGA-DEV, а не самостоятельный продукт. Любая
  правка — это будущий конфликт при синке. Прежде чем плодить локальный патч,
  спроси себя, нельзя ли обойтись без правки апстримного файла; если нельзя —
  правка должна быть узкой и осмысленной, а не переформатированием.
- Работа идёт только через ветку → MR в `airshadow-dev` (дев-стенд). Прямые
  коммиты и пуши в `airshadow-dev`, `airshadow-prod` и зеркало `main`
  запрещены — их режет гейт.
- `airshadow-prod` — реальный прод. Код попадает туда отдельным
  промоушен-MR'ом `airshadow-dev` → `airshadow-prod`, и заводить такой MR
  можно только по прямому решению владельца: мерж = выкатка на живой сервис.
  Задача с доски сама по себе основанием для промоушена не является.
- Синк с апстримом и разрешение конфликтов (особенно `src/pages/Login.tsx` —
  см. CLAUDE.md) владелец согласовывает лично: не запускай исполнителя на
  merge-конфликты без явного разрешения.
- Валидация — только сборкой и тестами (`npm run build`, `npm test`).
  Dev-окружение для проверки непригодно, «я посмотрел глазами» здесь не
  доказательство.
