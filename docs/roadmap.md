# Дорожная карта

Иерархия: **веха** (только здесь, на фордж не выносится) → **эпик** (милстоун
GitLab `[M1-E0N] Название`) → **задача** (`[M1-E0N-TK] Название`, привязана к
милстоуну эпика). Внеплановые fix/chore живут без кода.

## M1 — управляемый форк

Цель вехи: работа над форком идёт предсказуемо — изменения проходят через
проверки, а синк с апстримом перестаёт быть операцией «на память».

### M1-E01 — Процесс и гейты

Милстоун: [`[M1-E01] Процесс и гейты`](https://gitlab.com/airshadow/cabinet/-/milestones/2)

Развёртка харнеса выполнена (привязки, доска, метки, шаблон задачи). Остаётся
автоматика на стороне форджа: своего пайплайна у проекта нет, поэтому MR
сейчас мержатся без единой машинной проверки.

- `[M1-E01-T1]` пайплайн GitLab CI: `npm test` + `npm run build`, затем
  включение «мержить только по зелёному пайплайну»
- `[M1-E01-T2]` судьба мёртвых GitHub Actions после переезда на GitLab
  (решение владельца)

### M1-E02 — Синк с апстримом

Милстоун: [`[M1-E02] Синк с апстримом`](https://gitlab.com/airshadow/cabinet/-/milestones/3)

Апстрим публичный и читается анонимно, синк технически работает — но список
того, что мы держим поверх него, существует только в голове и частично в
CLAUDE.md (`src/pages/Login.tsx`). Эпик закрывает этот пробел.

- `[M1-E02-T1]` реестр локальных патчей форка
- `[M1-E02-T2]` замер дрейфа от `upstream/main` и план ближайшего синка

Реестр к #33 заведён и живёт в
[docs/architecture/two-modes.md](architecture/two-modes.md), раздел «Что остаётся
нашим в апстримных файлах»: девять апстримных файлов и два ключа локалей. Здесь
дублировать его не нужно — второй перечень разъедется с первым молча.

### M1-E03 — Продуктовые правки кабинета

Милстоуна пока нет: наполняется владельцем. Сюда идут задачи по
`area:cabinet` / `area:admin` / `area:api` / `area:i18n` — то, что мы меняем в
кабинете поверх апстрима (как пакет UI-правок «снизить визуальный шум»).
Заводить милстоун имеет смысл, когда наберётся первая связная порция работ.
